# 02 · 数据模型

> 数据结构、存储方案、两层数据体系、缓存策略

---

## 核心设计原则

- **无图谱关系**：不存储"上下游"或"范畴"关系。树结构由用户操作即时生成
- **两层数据体系**：
  - **聚焦（Focus）** → 创建独立 ConceptNode，拥有预设四问（micro/macro 各 4 个字段）
  - **子节点（Child）** → 统一为 custom_qa 记录，通过 `type: 'inquiry' | 'reference'` 区分追问和参考。挂在父节点下，可拖拽重组
- **缓存优先**：所有 LLM 生成结果首次生成后永久缓存

---

## 对象 1：ConceptNode（概念节点）

聚焦操作创建的独立节点。

```typescript
interface ConceptNode {
  id: string;                     // PK: MD5(term.toLowerCase())
  term: string;                   // 术语名称（如 "预解式"）

  // ===== 微观视角（默认）=====
  micro_intuition:    string | null;  // 🌳 动态直觉
  micro_definition:   string | null;  // 📐 看定义
  micro_application:  string | null;  // 🔧 看应用
  micro_motivation:   string | null;  // 📜 看动机

  // ===== 宏观视角 =====
  macro_territory:    string | null;  // 核心领地
  macro_logic:        string | null;  // 底层逻辑
  macro_touchpoint:   string | null;  // 现实落点
  macro_evolution:    string | null;  // 演化路径

  // ===== 追问 + 参考记录 =====
  custom_qa: CustomQA[];

  // ===== 元数据 =====
  created_at: number;              // Unix timestamp
  updated_at: number;              // Unix timestamp
}
```

### 字段状态机

```
字段值生命周期：
  null         → 未生成（显示 "点击以探索 →"）
  undefined    → 正在生成中（显示脉冲占位符）
  string       → 已生成（显示内容）
```

### 空值 vs 未生成

- `null`：用户从未展开过该预设问题，未触发过 LLM
- `undefined` / loading state（由 UI 层管理，不写入 DB）：LLM 正在生成中
- `string`：已生成并缓存

## 对象 2：CustomQA（追问条目 + 参考节点）

追问和参考统一存储为子节点，通过 `type` 区分。

```typescript
interface CustomQA {
  id: string;                // UUID
  type: 'inquiry' | 'reference';  // 追问 或 参考
  term: string;              // 被追问的术语（追问时）或空字符串（参考时）
  question: string;          // 节点标题（"算子是什么？" 或 ""）
  answer: string;            // LLM 答案（追问时）或用户原文（参考时）
  parent_node_id: string;    // 指向树中父节点 ID（树结构由此外键重建）
  created_at: number;
}
```

### 子节点类型区别

| 操作 | 创建什么 | type 值 | answer 来源 |
|---|---|---|---|
| 右键追问 / + 模板追问 | CustomQA | `'inquiry'` | LLM 流式生成 |
| + 按钮 → 添加参考 | CustomQA | `'reference'` | 用户粘贴/上传的原文 |

### 追问 vs 聚焦：数据层区别

| 操作 | 创建什么 | 数据去向 | 是否有预设四问 |
|---|---|---|---|
| 双击聚焦 "X" | ConceptNode { term: "X" } | IndexedDB concept_nodes 表 | ✅ 有（4个预设字段） |
| 追问/参考 "X" | CustomQA { term: "X" } | 父节点的 custom_qa[] 数组 | ❌ 无（仅一条记录） |

## 对象 3：LLMConfig（LLM 配置）

```typescript
interface LLMConfig {
  api_key: string;       // API 密钥（明文存储，设置页显示警告）
  base_url: string;      // 默认 "https://api.openai.com"
  model: string;         // 默认 "gpt-4o"
  max_tokens: number;    // 默认 1024
  temperature: number;   // 默认 0.7
}
```

存储位置：`localStorage`，key = `"llm_config"`

## 对象 4：TermList（用户术语表）

每次双击聚焦的术语自动追加。用于参考节点粘贴时的术语匹配标注（无需调 LLM）。

```typescript
// localStorage key = "term_list"
type TermList = string[];  // 术语名称数组，小写去重，如 ["预解式", "算子", "谱集", ...]
```

### 行为
- 双击聚焦 → 术语追加到表（去重）
- 参考节点粘贴文本 → 遍历术语表，对文本中出现的术语自动包裹 `[[术语]]`
- 跨 session 持久化（localStorage）
- 不设上限

## 对象 5：CognitionPath（认知足迹）

仅存于 React State，不持久化。

```typescript
interface PathNode {
  term: string;
  node_id: string;       // ConceptNode.id
  timestamp: number;
}

interface CognitionPath {
  nodes: PathNode[];     // 最多 50 个
  current_index: number; // 当前焦点位置
}
```

### 足迹行为规则

- 双击聚焦 → 追加新节点到数组末尾，current_index 移到末尾
- 点击足迹链中的历史节点 → current_index 移到该位置，**截断之后的所有节点**
- 最多 50 个节点，超出时移除最早节点
- 刷新页面 → 清空（不跨 session）

## 对象 6：WorkGroup（工作组）

项目式隔离。每个工作组有独立的根术语列表、导图缓存、足迹上下文。

```typescript
interface WorkGroup {
  id: string;                    // UUID
  name: string;                  // 用户命名（如 "泛函分析学习"）
  root_term_ids: string[];       // 入口概念节点 ID 列表
  guide_map: GuideMapNode | null; // 缓存的导图（null = 未生成）
  created_at: number;
  updated_at: number;
}
```

存储：IndexedDB `work_groups` 表

---

## 对象 7：GuideMapNode（导图节点）

教材目录式层级结构，缓存于工作组中。

```typescript
interface GuideMapNode {
  term: string;                  // 术语名称
  children: GuideMapNode[];      // 子节点（层级缩进）
}
```

- 首次进入导图模式 → 若 `guide_map === null`，显示"生成导图"按钮
- 已有导图 → 显示"Extend"按钮（增量扩展）
- ✓ 标记：前端渲染时对比术语表，已存在的术语标记 ✓

## 存储方案

### IndexedDB

| 数据库名 | 表名 | 主键 | 索引 |
|---|---|---|---|
| `omni_explore_db` | `concept_nodes` | `id` (MD5) | `term`, `updated_at` |
| `omni_explore_db` | `work_groups` | `id` (UUID) | `name`, `updated_at` |

```typescript
// 使用 idb 库封装
import { openDB } from 'idb';

const db = await openDB('omni_explore_db', 1, {
  upgrade(db) {
    const store = db.createObjectStore('concept_nodes', { keyPath: 'id' });
    store.createIndex('term', 'term');
    store.createIndex('updated_at', 'updated_at');
  },
});
```

### localStorage

| Key | 值 | 说明 |
|---|---|---|
| `llm_config` | LLMConfig JSON | 明文存储，设置页面顶部显示警告横幅 |
| `input_history` | `string[]` | 最近 20 条输入历史 |
| `term_list` | `string[]` | 用户级术语表（双击聚焦自动追加，去重） |
| `inquiry_templates` | `string[]` | 预设追问模板（如 ["{term}是什么？", ...]） |

## 缓存策略

### 写入时机

| 操作 | 写入时机 | 写入内容 |
|---|---|---|
| 动态直觉生成完毕 | 流式输出结束后 | `micro_intuition` |
| 展开某预设问题 | 流式输出结束后 | 对应的 `micro_*` / `macro_*` 字段 |
| 追问生成完毕 | 流式输出结束后 | 追加到父节点的 `custom_qa[]` |

### 读取策略

```
用户操作 → 查 IndexedDB
  ├─ 命中 → <200ms 直接渲染缓存内容
  └─ 未命中 → 调 LLM → 流式渲染 → 写入 IndexedDB
```

### 缓存失效

- 用户主动操作：右键 → "换角度" 或 "刷新此节点" → 重新调 LLM → 覆盖原缓存
- 无自动过期机制（MVP 不做 TTL）
- 无缓存大小限制（MVP 不做 LRU 淘汰，由浏览器 IndexedDB 配额自然限制）

为支持悬停预览，可维护一个内存中的术语→缓存映射：

```typescript
// 启动时从 IndexedDB 全量加载到内存 Map
const termCache: Map<string, string> = new Map();
// key: term.toLowerCase()
// value: micro_intuition 的第一句

// 悬停时：termCache.get(term) → 有则显示首句，无则不显示预览
```

**注意**：此索引仅用于悬停预览，不影响核心数据模型。
